## 结论与发布建议

- **定位质量改善**：实际编辑文件召回率提升 9.4 pp，全目标命中率提升 12.5 pp。
- **成本改善**：平均模型延迟下降约 20.8 秒，completion tokens 减少 14,897。
- **核心目标未达成**：模型要求额外 `read` 的比例反而增加 25.0 pp。逐样本看，增长集中在短任务和高噪声大上下文；`complete=false` / `OMITTED` 很可能被模型解释为仍需补读。
- **样本限制**：仅 8 个真实调用，且任务标签是“调用后实际编辑文件”，会混入 fast_context 之后用户追问或任务扩展。结果适合作为方向性证据，不宜宣称统计显著。
- **建议**：保留本次 span、边界和 omitted 能力，但先作为输出契约增强发布；不要承诺已减少补读。下一轮应减少重复元数据，并把 `complete` 拆为 `segmentComplete` 与 `contextComplete`，再做不少于 30 个真实调用的复测。
