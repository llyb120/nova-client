本轮精简上下文组 B 成功 6/6，对照组 A 成功 5/6，没有假完成。累计 API token 从 541,101 降至 330,274，减少 38.96%。但不能据此宣称稳定提速：仅比较双方均成功的五个任务，总耗时为 A 261.68 秒、B 262.73 秒，B 反而多 0.40%，五对中仅两对更快。相同五个成功任务的 token 从 336,416 降至 238,916，减少 28.98%。

成功数在本轮样本中更好；每个通道/任务仅一对，不能当作普遍准确率提升或统计显著的证明。

## 唯一未完成任务与恢复行为

A 的 Chrome 表单任务最终为 `yielded`，而非 `completed`，且业务验收失败。192.38 秒、三次阶段执行后，标题已填成 `September review`，优先级仍为 `Normal`，备注仍为 `Old notes`。日志显示重复点击下拉框，并出现 `params.tabTag: required` 和空决策解析错误。不能仅凭这一轮断言累计历史是失败的唯一原因。

B 的同一任务在 127.61 秒内完成，优先级为 `High`、备注为 `Checked by Nova`，最终页面验收通过。B 也遇到过“先观察再操作”校验拒绝和空决策，随后恢复完成，说明修复后的恢复路径确实在真实模型测试中被触发。

本轮 112 次 GUI 模型请求均返回 HTTP 200，模型 ID 全部匹配；其中三次 `finish_reason=length` 且正文为空（A 两次、B 一次），不能把 HTTP 成功等同于有效决策。最终记录里这些请求的 token 均已计入。

回归测试：47 passed、0 failed、2 ignored。全轮真实任务为 11/12 成功；工作流之所以显示 failure，是因为验收要求 12/12，不是密钥无效或没有执行测试。
