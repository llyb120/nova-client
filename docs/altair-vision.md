# Altair 视觉代理

## 分工（2026-10-10 重设计）

Altair（设置里选的 Lyra 识图模型，`src-tauri/src/altair.rs`）只当主模型的眼睛，不做任何决策；判断全部由主模型完成。目的是让截图不进入主模型上下文。

- **出口过滤**：剑来（`jianlai::execute`）、WebView（`native_browser::execute`）、Chrome（`native_browser::execute_chrome`，UI 调用除外）的返回在最后一步经过 `altair::filter`。Altair 开启且结果带截图时：
  - 一次请求把截图（最多 4 张，含滚动中间帧）发给 Altair；
  - 返回 `vision`：`summary`（画面概述）、`answer`（回答调用参数 `look`）、`targets`（最多 20 个可操作目标 `v1…`，坐标已换算回 imageId 像素）；
  - 删除 `images[].path`、`path`、`imagePath`，三个转换器（MCP Node、Codex、Lyra）就不会附图。`imageId`、`snapshotId` 保留，坐标校验链路不变。
  - 失败（未配置、超时、无效 JSON）时保留原图并写 `vision.error`，主模型不会看不到画面。`vision:"raw"` 主动要原图。
- **target 定位**：坐标动作可以不写 x/y，改写 `target`：
  - `vN`：从该 snapshotId 的 `vision.targets` 取坐标，不再请求模型（内存表保留最近 32 个快照）；
  - 文字描述：`altair::ground` 在该快照截图上定位，置信度 < 0.6 不执行。
- **连续操作（剑来）**：一次 act 里带 target 的多步由 `jianlai::vision_act` 逐步执行。每步定位后单独走原有 act 校验（快照/窗口/遮挡/像素守卫），反馈截图等界面稳定后作为下一步依据；`vN` 在画面变化后按其标签重新定位。任一步失败即停，返回 `steps`，不重放。最后一张图再经出口过滤变成文字。
- **浏览器**：DOM 动作照旧用 frame/ref；`click_at/move/scroll_at/drag` 支持 target，按该 snapshotId 自己的截图定位（同一批共用一张图）。
- **run（Altair 开启）**：只执行主模型给出的 `plan.steps`（必填，1–24 步），本地在最新 DOM 上绑定、步间等页面稳定；歧义或 expect 不成立时交回。`expectedText` 可选，给出时才做最终文字核验。不再有 Altair 自动驾驶或强制委托。
- **关闭兼容**：按 `e661418` 的关闭路径处理。原图直接返回，不调用 Altair；浏览器 run 需要有效 `snapshotId` 和 `plan.task/authorization/expectedText`，缺省或空 steps 只返回 handoff、不执行动作，有 steps 时执行后必须核验完成条件。保留 `controlNames/useExperience` 旧参数的格式校验，但不恢复自动决策。桌面 run 仍等价于 act，并提示主模型核对新截图。旧 `advise` 调用在三个工具中均返回 disabled、不请求模型。运行报告统一使用 `altairRun`；不恢复 JEV 服务或配置。浏览器摘要、快捷键等独立修复保留。

关闭状态 dev 回归：`node scripts/altair-vision-live.mjs --run --altair-off`。检查原图交给主模型、Canvas 识读和坐标点击，以及 advise 关闭返回、无 steps 的 handoff、有 steps 的执行核验、stop 后旧快照被拒绝。去掉 `--altair-off` 检查视觉代理模式。快照读取不使用上一条已结束操作的取消令牌；执行中的取消保护、会话可见性和 stop 作废快照仍保留。

实测（`commandcode/deepseek/deepseek-v4.1-flash-fast`，合成 2000×1200 图）：`see` 约 5.3 秒，两个色块描述正确、目标中心误差 < 15px；`ground` 约 3.4 秒，误差 < 10px。用例 `cargo test --lib probe_live_see_and_ground -- --ignored`（`NOVA_DATA_DIR`、`NOVA_ALTAIR_PROBE_MODEL` 指定配置）。

### 2026-10-10 性能验收边界

真实榜单截图离线压缩：1600×719 PNG 307726 字节 → 1024×460 JPEG 45754 字节，准备约122ms；单次合成视觉定位（不执行输入）约4.17秒，坐标正确。真实 dev 回归曾出现网关返回思考耗尽 512 总 token，未达到一次委托完成；思考模型预算保留2048。后续有界原始 SSE 对照查实 CommandCode Chat Completions 的关闭参数必须为 `reasoning_effort:"off"`：只发 DeepSeek 原生 `thinking.type:"disabled"` 仍返回 reasoning_content；`reasoning_effort:"none"` 被400拒绝且报出枚举；改为 `off` 后同一图文请求无任何推理字段（约2.19秒）。共享 provider 按精确 host 适配此规则，不修改 DeepSeek 原生接口或用户选择的 high；不能把该单次对照当作整页连续驱动已验收。浏览器摘要同60元素预算、三张真实快照减小约27%，不包含图片/MCP外层封装。

追加实机回归：关闭思考后多次 Altair 调用 `thinkingChars=0`，但完整任务仍多次 handoff。限定排序回归两次 DOM 点击已正确改为降序并加载前五行，run 仍因完成判断低置信度而 handoff（外部工具约18.6秒）；不算验收通过。另修复 Altair 误用携带旧截图：坐标复用仍有现场像素校验，但视觉决策只接受当前 snapshot 自己生成的图片，不把相同 URL/视口视为图像内容未变。该守卫回归通过，后续仍需改善语义完成核验，不降低阈值掩盖失败。

### 完成核验与动作选择分离

结果页有真实 rows、loading=false、无覆盖缺口时，先独立核验完整目标，而不是把 DONE 与动作/路径预测混在一起。证据保留 URL、当前筛选文字、选中集合、日期、独立表头和最多10条真实数据行；不携带旧动作的 Loading 文案、引用和候选控件。只在 URL/行数据/选中集合/日期/排序语义状态变化时重查，普通 ref/弹层变化不重问同一结果。高置信 yes 之后必须刷新，证据不变才完成；数据行缺失、仍加载、有观察缺口不能走此提前完成路径。整体证据超过40k字符时跳过该可选检查，继续原有有界驱动，不截掉证明后强行通过。非表格目标继续使用原有完成决策。

`completionChecks` 返回独立核验结果与耗时；纯表格数据更新也记入 `history[].effect.resultsChanged`，不再误报“页面没变化”。真实降序快照回放：旧证据约9.1k字符、yes置信度0.37；精简后约4.6k字符、yes置信度0.86、约518ms。空数据、反序数据和错误地区反例均未越过完成门槛；不降低0.6阈值。此为真实服务的静态页面证据回放，不等同于整轮浏览器实机验收。

## 操作头 + 目标头（参考 browser-use/jev-ultrafast）

目标模式的 JEV 请求不再把约 90 个元素和 observe/done/defer 放进一道扁平选择题。同一次请求里，`operation` 题只在 CLICK/TYPE_TEXT/PRESS/SCROLL/WAIT/DONE/BLOCKED 中选择；每种有候选的操作各有一道 `*_target` 题，只包含该类型可用的候选。只有被选中操作对应的目标会执行，其余目标头的答案会被忽略。WAIT/DONE/BLOCKED 分别对应执行器原有的 observe/done/defer，同屏后续路径 `next_1..3` 保持不变。state 改为结构化 JSON（页面证据、刚出现的控件、最近 6 步动作及 effect），不再发送字符串形式的决策树。展开折叠分组时改用一道单选题并提供 defer 选项。JEV 返回 429/503/529 时，按 0.5 秒、1 秒退避后最多重试两次。

输入文字只来自主模型的 `plan.inputs` 或目标中明确写出的搜索值，不由小模型自行生成。搜索值可承接紧邻逗号前的字段语境，例如“打开 Region，在弹出的下拉列表中选择 United States”；不跨句或将整句中别的字段值混入，复杂/歧义绑定仍用 inputs。派生值仅作为搜索候选，不自动 reflex 填写。值只写在 expectedText 时，必须有唯一与 task 字段语境对应的面板搜索框才能派生，多个同类框仍要求显式 inputs。宏回放和概率分布校验也没有引入。

Altair 只判断当前一步：不发送重复的 `next_1..3` 候选列表，只需回答 operation 及被选中的目标题，执行后重新观察。普通模型输出上限 512，声明带思考的模型保留 2048 总 token（实测部分网关收到关闭思考参数仍输出思考，512 会在动作 JSON 前被耗尽）；不改变用户模型设置。每层 latency 保留图片原/发送尺寸、字节数、图片准备、首正文/总耗时与思考字符数。不能只看总耗时判断网络或图片慢。回退失败直接交接，不为同一故障换候选批次或核验重试重复等待；失败原因与每层耗时保留在日志。Top N 必须读取指定排序下的前 N 条数据，不能改成最大 N 条倒序展示，空值如实说明。浏览器摘要压缩重复正文与 DOM 元数据，完整观察仍存 documentPath，内部决策和校验不使用截短副本。决策证据中的大表先取 10 条真实数据行并标记 previewTruncated，而非因预算不足丢掉整张数据表，避免将独立空表头误判为无数据。

## 决策树执行（2026-09-23 重构，取代下文"执行循环""同屏路径"中逐步请求 JEV 的做法）

旧实现每个动作都请求一次 JEV（做一步想一步），且候选多达 256 个，既慢又容易选错。现在 `run` 的每次观察都走同一棵树，首个成立的节点执行：

| 节点 | 条件 | 动作 | 请求 JEV |
| --- | --- | --- | --- |
| guard | 跨站、观察缺口、180 秒预算、同一状态已操作 3 次 | 交回主模型 | 否 |
| wait | 页面 `loading` | 每 250ms 刷新，最多 4 秒 | 否 |
| reflex | `plan.inputs` 唯一绑定且当前值不同 | 本地一批 `fill`（最多 8 个；中断的填写最多重试一次） | 否 |
| path | JEV 路径的下一步在新 DOM 中同节点同状态（key 完全一致）、URL 不变、没有新控件出现、动作后 200ms 复看页面稳定 | 直接执行 | 否 |
| jev | 信息边界：新菜单/新页面/路径失效 | 一次请求选出当前一步，并预测最多 3 步同屏后续（`next_1..3`，可选 `replan` 截断） | 是 |
| fallback | `defer`（已翻完候选批次且页面未变化）、JEV 不可用、执行不明确、点击/填写/完成/分组选择/步骤绑定的置信度 < 0.6（未返回置信度视为可信） | 返回最新观察，主模型兜底 | — |

- 候选排序：授权 fill > 已填好且聚焦的输入框回车提交 > 上一步刚出现的控件（`[新]`，即打开的菜单/弹层/结果）> 与目标/输入/controlNames 词语重合的控件 > 其它。每批 90 个，按 DOM 顺序编号 `a01…`；JEV `defer` 且还有未展示的候选时换下一批（每个状态最多 3 批）。
- 同类集合折叠（2026-09-23 日期面板会话修正）：同角色、同名称形状（数字归一，如日历日期格 1…31、每行同名按钮）≥8 个时折叠为一个 `gNN` 分组，不再挤掉唯一控件（如 `Last 26 Weeks` 预设）；选中分组后第二次请求只含组内成员；名称被目标直接提及的成员仍单独列出。该会话中日历 142 个候选使 JEV 两次 defer。
- 已填写且聚焦的授权输入框提供 Enter/Tab 候选，由 JEV 选择。
- 提示词要求按语义跨语言匹配（近半年≈Last 26 Weeks/Last 6 Months）、优先使用预设快捷项；日期被页面按周归一化相差几天视为已完成。defer 交接原因不再强调候选数量。

  - 每批候选上限 60→90。分组折叠后大多数页面能全量展示，排序只用于裁剪拥挤页面。
- 2026-09-24 基于 dev 会话 913c790c 第二轮（8 次 run、多次交接）的修正：
  - 智能搜索输入：任务文字里写明、页面上看不到的值（引号内文字或英文专名，如 `United States`），会成为搜索/筛选框的输入候选。前提是该值与该字段的上下文词（如 Region）出现在同一句里。候选标注"来自任务文字"，由 JEV 选择，不会自动填写；全站搜索框因上下文不匹配不会得到候选。主模型不必再为地区搜索补 `inputs`。

  - 动作效果：`history[].effect` 记录每步的实际变化（`url` 跳转、`newControls` 新控件、`newText` 新文字、`changed` 状态变化）。点击后若看不到变化，300ms 后再看一次，确认无变化才提示"无效，换目标"。JEV 据此区分"已排序"和"只弹出了释义"。

  - 返回瘦身：run 内部的 inspect/act 摘要改为 2500 字、30 个元素（JEV 仍读取完整观察，不受影响）。`jevRun` 只保留结果、原因、每步效果和精简的决策记录，完整决策树只在交接时返回。此前 4 次 run 的返回过大被存成文件，主模型要用 shell 去读。
- `observe`（WAIT）在本地轮询直到页面有变化才再问 JEV，连续无进展 15 秒交回；JEV 连续第 3 次选 WAIT 时直接交回主模型。
- JEV/路径/分组每次动作后先轮询到连续两次观察一致（最多 1 秒）再决策，避免界面晚一拍渲染时就做下一步。
- `done` 需在新观察中控件/URL/表格状态不变才算完成。
- 输出新增 `jevRun.reflexActions`、`jevRun.trace`（树节点轨迹），`decisionTree` 为运行时树及当前 JEV 分支；`cachedActions` 统计按已校验路径执行、未请求 JEV 的动作。

## 执行循环

1. 从当前 DOM 枚举可操作元素，为每个候选分配本轮编号。候选携带名称、角色、所属区域、框架、表格列和状态；执行参数保留在本地。
2. JEV 选择编号，或返回 `observe` / `done` / `defer`。加载、跳转、提交后的短暂等待用 `observe` 在本次调用内刷新，不交回主模型；真实阻塞才 `defer`。不按任务关键词自动裁剪候选，也不因按钮同名就删除候选。
3. 执行器使用真实 `frame/ref`，先激活明确绑定的 Chrome 标签以避免后台渲染限速，再沿用浏览器已有的节点身份、遮挡、焦点和输入结果校验。
4. 每次操作后重新获取 DOM。点击、滚动或页面变化后重新决策；完成判断还要经过一次新观察核验。
5. DOM 定位/悬停校验失败且执行器确认尚未按下鼠标、尚未填写时，最多三次基于新 DOM 重新决策；不重放旧引用。已确认执行成功但反馈读取失败时，仅补读 DOM，保留已执行记录和去重保护。模型不可用、证据不足、超出授权、执行不明确或预算耗尽时，返回最新观察、已执行历史及剩余目标，由主模型接手；不自动重放。

主模型应一次委托完整的可授权流程，不把每次点击拆成一个 `run`。每段等待最多 5 秒，按 250ms 间隔刷新 DOM；加载证据未变化时不重复请求 JEV，观察不消耗动作额度。无加载标记的稳定菜单会在 500ms 后重新判断一次；仍无法推进则完成剩余等待，不因导航外壳先出现而提前交还。状态变化检测覆盖全部控件，不受提示词摘要截断影响；defer 前刷新检查，页面已有变化则继续本次 run。完成核验期间页面变化时留在循环中重新判断。同一动作在执行后的当前状态中也会去重，防止刷新期间重复提交。

`plan.inputs` 的 name 必须原样复制唯一目标的 DOM name 或完整 fieldContext；role 可选且只限制角色。同名日期框用 `Week ~ [field 1/2]` 等实际上下文区分。执行器先精确绑定再生成 fill 候选，找不到或存在多个匹配时不猜测；missingInputs 返回 fieldContext 供主模型修正委托。无名字段仍可通过唯一完整 fieldContext 填写。

编号是交给模型的文字提示，类似 Vimium 的元素选择模式，不需要在网页上绘制标记。原有快照引用每次刷新都会改变；新增的文档内节点身份只用于判断计划是否仍适用，不能代替最新 `ref` 执行。

自定义文字控件的扫描额度只计入可见节点；隐藏和屏幕外的表格节点不能挤掉文档末尾新打开的菜单。仍沿用点击前的真实命中测试，DOM 中有编号不表示一定可以安全执行。

候选筛选参考 [Vimium LocalHints](https://github.com/philc/vimium/blob/5aa29614bf1dce05e0d316f8c38722e17f9b38c3/content_scripts/link_hints.js#L1124)：遍历 DOM 与生成操作提示是两件事。优先原生控件、交互角色及明确点击属性；普通 `tabindex` 容器不成为点击候选，包裹真实控件的语义 span 去重。为无语义的框架控件保留 `cursor:pointer` 边界回退，但不再把继承 pointer 的内部文字逐个编号。与 Vimium 一样保留可见性和命中检查；不同列或记录的同名控件仍是不同目标。

## 同屏路径

纯点击或滚动页面只判断当前一步；有可填写候选时，按字段数加一步、最多 4 个选择题推演路径。第一题始终只判断当前能推进目标的动作，不要求预知完整路径；后续题返回对应位置的候选。第一步必须来自本轮候选；后续回答只保留合法且不重复的前缀，重复、缺失或无效的后续题不作废已经有效的第一步。未知后续页面用 `defer` 截断路径。

目前只复用连续填写之后的剩余路径：每步刷新后，除预期字段值外，完整 DOM 状态必须一致，后续目标节点必须仍是原节点，并重新绑定最新引用。节点替换、验证提示、导航、菜单展开、遮挡和其他变化都会丢弃剩余计划。点击后的路径暂不复用；扩展它需要明确的动作后置条件。

## 边界

- 默认每次 `run` 最多 32 次动作，`maxActions` 可设 1–64，时间预算 180 秒。
- 每次 JEV 请求最多 60 个 DOM 候选，按相关性分批，不再因超过 256 个而交接；`controlNames` 提高指定控件优先级。
- 支持 DOM 点击、明确委托的填写，以及页面/内部容器的纵向滚动。输入值由主模型提供；同名且无法唯一绑定的输入框交回主模型。
- 视觉、敏感输入、授权不明、原生弹窗和不支持的交互由主模型处理。已明确授权的提交仍须逐步核验，不得重复。JEV 的文字建议不是视觉定位、操作授权或业务成功证明。
- `jevRun.requestCount` 记录实际请求，`cachedActions` 记录通过新 DOM 校验后复用路径的决策次数，`observationRefreshes` 记录内部等待刷新次数；`history` 用于核对已执行操作。

滚轮候选覆盖页面和任意标签的嵌套滚动区，包含上下左右及 RTL 横向位置。候选携带区域角色、方向、当前偏移和可视长度，步长为视口的 80%（80–640 CSS 像素）。滚轮命中允许落在子按钮上，但不让嵌套滚动区抢走父区域滚轮；执行后最多 600ms 等待位移稳定，返回 `scrollFeedback.changed`，不能把输入发送成功当成已经滚动。

每次决策从当前 DOM 重建条件执行树：`interact`（目标可操作或有入口）、`reveal`（滚动显露）、`wait`（加载）、`verify`（核验）、`blocked`（真实阻塞）。树由执行器生成合法叶子，JEV 在同一次请求中判断条件并选择叶子，不额外调用主模型规划。每次动作反馈后旧叶子失效，重新判断先点击还是先滚动。`jevRun.decisionTree` 返回最后一次决策的树，`decisions[].treeRevision/treePath` 记录每次选择；它不是预先猜测整条点击路径。

无文字的可聚焦表头控件也可作为点击候选，`column.name/index` 给出所属列；不能将表头释义文字直接当成排序入口。防重放状态采用 URL、控件值/选择/展开/排序状态、滚动位置与表格结果，不再把 tooltip 正文变化当成进展；返回已访问状态时，已尝试动作仍被排除。执行结果不明确仍交接，不自动撤销业务操作。

页面等待现在允许连续 15 秒无进展（此前为 5 秒），观察到状态变化后重新计时；整个 run 仍受 180 秒上限约束。等待循环只刷新 DOM，不重复调用 JEV。

日期区间的两个输入框不再因共用容器而丢失字段上下文：带区间分隔符的双日期字段保留最近标题（例如 Week 或 Release Date）及区间内位置。只读日期框同样携带上下文供点击选择；字段用途变化会使旧引用失效，即使 Select date 占位文字未变。此处理在现有 DOM 采集内完成，不增加浏览器往返。其它多字段容器仍不推测归属。

这些日期控件的当前值（仅空值或 YYYY-MM-DD 格式）作为独立 dateFields 完成证据置于摘要前部，不依赖填写授权，也不因控件动作已去重或普通 DOM 摘要截断而消失。避免预设选择已生效后仍反复调整日期；任意文本输入值仍沿用原有披露规则。

选择状态同样以 selectionFields 置于摘要前部，保留原生布尔值及 ARIA 的 true/false/mixed，包括已去重动作对应的未选中项。JEV 核对实际选中集合再应用筛选：选项出现不代表已选中，已选中的目标不能再次点击取消；“仅一个地区”还须排除其它选中项。最多保留64个可见选择控件，超出明确标记 selectionFieldsTruncated，不把截断集合当作完整证据。不增加 DOM 采集或模型往返。
