# 剑来 / Chrome 操作经验

剑来、Chrome、WebView 共享本机能力路径图谱，按工具与应用/网站隔离。图谱不是独立经验卡片列表：相同入口条件下，共同操作前缀合并为树，分支显示可以继续做什么、能完成哪些目标，用于规划。没有训练会话、辅助模型或模型参数训练；当前执行任务的模型负责从成功轨迹提炼语义步骤。工具说明对所有使用同一 schema 的宿主生效。

底层仍用 `tool-experiences/routes.json` 保存已验证路径与证据，搜索时投影为前缀树，旧数据无需迁移。不同入口条件不合并，同名步骤出现在不同前缀下也不合并，避免虚构跨页面捷径。比较步骤、入口条件、检查点与检索 `prefix` 时忽略空白、标点和大小写（“打开 报表。”与“打开报表”视为同一步），不做语义相似合并。

## 知识图谱页面

在「设置 → 高级」打开「显示知识图谱」并保存，侧栏室女座旁会出现入口；默认关闭，关闭后退出图谱回到首页。页面一次展示所有工具、应用/网站的全部有效路径和全部起点，不限制深度，也不受工具搜索的12条路径限制。失效路径不会显示。

操作图使用彩色圆形节点和独立有向边：入口条件是起点，同一工具/应用内同名操作汇总为操作概念，同名任务目标连接不同来源。支持多起点汇合、双向回路和重复操作自环。实线记录相邻操作的顺序，虚线表示达成目标；每条边保留来源路径与步骤序号。概念汇总不证明页面状态相同，也不允许任意拼接路径；工具规划接口继续使用保守的前缀树。

支持拖动、缩放、全图总览、按步骤/目标/应用/网站搜索定位。搜索与点击节点始终保留全图，右侧可查看全部前驱、后继与完整路径；点击连线查看来源，选择路径可高亮并核对入口条件、完整顺序和成功检查点。保存新经验后点击「刷新记录」更新。

剑来、Chrome、WebView 均接入经验保存，按工具分组展示；没有记录时显示空状态。

页面验证：`node scripts/knowledge-graph.test.mjs`（需本机 Edge，或用 `TEST_BROWSER` 指定 Chromium 路径）。

经验调用按需触发，不是任务开始/结束的必经流程；已知路径直接操作，不因新任务或切换应用/网站/子任务机械检索，浏览器普通成功无需保存（回合正常结束时自动记录轨迹），不为记录经验打断连续步骤。剑来没有自动记录，未照已有路径、经2步以上操作并以截图确认成功时，结束前 experience_save 一次。图谱增强检索结果和规划能力，不改变这一触发原则。

## 自动提供与自动记录

图谱的价值取决于有没有数据、模型会不会用，这两件事不依赖模型自觉：

- **自动提供**：每轮对话首次观察某应用/网站（剑来 `windows`/`screenshot`/`activate`，Chrome/WebView 返回页面的操作）时，若库里有该 scope 的有效路径，结果附带 `experienceHint`：按成功次数与更新时间排序的前8条路径（已有模型验证路径时只列验证路径，自动轨迹仅计入 `totalRoutes`，需要时 `experience_search`）（目标、入口条件、步骤、已知坑），过长用 `…` 截断。同一轮同一 scope 只附带一次，回合结束后重置；读库失败静默跳过且不占用本轮提示。
- **自动记录**：JEV `run` 通过完成条件校验且计划至少2步时，按计划自动保存路径（`outcome=success`），结果的 `experience` 字段给出 id。入口条件取起始页面路径，数字段视为记录 id 归一为 `*`；`fill` 的输入值属于任务数据，不写入步骤；超过12步时相邻步骤合并。同一路径在其它会话再次成功即去重并升为 `reused`。
- 模型手动保存专注于自动记录覆盖不到的内容：非显然入口、踩过的坑（`pitfalls`）、非直觉顺序；复用已有路径后用 `experience_feedback` 报 `success`/`invalid`，让可信度上升或剔除失效路径。
- **自动轨迹（不依赖 JEV）**：Chrome/WebView 每次 `act` 完成的点击、填写、按键按目标控件的 role 与可见名称记为语义步骤（如 `点击 button「查询」`、`填写 textbox「用户名」`，不含输入值、ref 或坐标；名称中4位以上数字替换为 `#`），act 之间页面路径变化（goto/back/open）记为 `打开页面 /路径`，连续重复步骤去重。回合正常结束（`end_turn`/`max_turn_requests`）时把 2–48 步的轨迹存为路径：任务为 `从<入口路径>操作到「终点页标题」`，检查点为终点页标题与路径，`source=auto`/`verification=auto_recorded`；取消、出错的回合只丢弃轨迹。起点与终点相同的自动轨迹合并为一条并保留步骤更少的版本，绕路随重复操作逐步淘汰；每个网站最多保留最新10条自动轨迹。模型在同一回合对该网站 `experience_save`/`experience_feedback` 后丢弃轨迹，避免重复。JEV 执行的动作不进轨迹（由 run 自行保存）。剑来只有坐标操作、没有 DOM 语义，不做自动轨迹。
  - 已知上限：正常收尾只表示模型认为已完成，不等于业务成功；轨迹包含绕路与试探步骤；列表行中的人名等非数字业务文本仍可能进入步骤名；Chrome 会话按工作目录匹配，同一目录并发运行的会话会合并轨迹；轨迹只在内存中（最多32条、2小时），Nova 退出即丢失。

## 加载与提炼时机

1. 仅路径不熟悉、操作受阻、需要了解可用能力或用户要求复用经验时调用 `experience_search`，传通用 `task` 和 `scope`；`task="*"` 浏览能力。检索时优先用 `graph` 规划，根的 `conditions` 表示入口条件，`children` 表示下一步分支，每个节点的 `canDo` 表示沿此前缀能完成的目标，`routeIds` 关联 `graph.routes` 内完整验证路径及检查点。可传原文步骤数组 `prefix` 下钻，返回仍保留完整入口路径。首次观察后核对 `conditions`，每一步依据当前界面重新定位。不跨路径拼接成已验证计划。
   - 图谱最多展开12条完整路径；`capabilities` 最多列30个候选目标/id，`totalRoutes` 为前缀下有效路径数。`graphTruncated` / `capabilitiesTruncated` 表示截断，可缩小目标或前缀继续查询。
   - 检索覆盖目标、入口条件、步骤；无关键词匹配时仍返回能力图谱供规划，而非宣称应用没有能力。空库正常探索。旧 `experiences` 字段保留最多3条匹配结果供兼容，不是主要规划接口。
2. 仅发现有复用价值的新路径或修正旧经验，且可见结果证明成功后，才调用 `experience_save`；填写适用条件、去掉试错的步骤、成功检查点、已知坑和脱敏的可见证据。未完成、中断、仅仅输入执行成功时不保存。
3. 实际复用已有路径且有值得记录的结果时，才调用 `experience_feedback`。独立会话再次成功后由 `initial` 升为 `reused`；同一会话重复保存/反馈不累计成功数。此处独立验证按会话去重，同会话内多次任务保守地只算一次。
4. `transient`（超时等）与 `precondition`（前置条件不符）记录原因，不降低路径可信度；确认页面变化或路径失效才报 `invalid`，停用该路径。修正后成功的路径另存，不覆盖已失效路径。

## 调用

```json
{"operation":"experience_search","experience":{"scope":"https://www.tapd.cn","task":"查找下一迭代"}}
```

成功后（Chrome 另需当前 `tabTag`）：

```json
{
  "operation":"experience_save",
  "tabTag":"从tabs取得",
  "snapshotId":"从最新inspect或截图取得",
  "experience":{
    "scope":"https://www.tapd.cn",
    "task":"查找下一迭代",
    "conditions":["已登录并进入目标项目"],
    "steps":["打开迭代列表","按日期定位当前迭代之后的迭代"],
    "checks":["核对项目名称、迭代标题与起止日期"],
    "pitfalls":["不要只凭列表位置推断下一迭代"],
    "outcome":"success",
    "evidence":"最新页面已显示目标迭代，标题与日期已核对",
    "redacted":true
  }
}
```

剑来用相同操作与字段，省略 `tabTag`；`scope` 使用 `windows` 返回的准确 `app` 名称，先截目标应用窗口。反馈仅需 `scope/task/id/outcome/reason/evidence/redacted` 以及顶层 `snapshotId`（Chrome还有 `tabTag`）。

## 边界

- 保存/反馈必须引用本会话该工具最新、180秒内的观察，应用/网站必须匹配。搜索不需要打开Chrome连接。
- 工具校验观察的来源和时效；业务成功与脱敏内容由当前模型核实，因此标记为 `model_verified`，不是工具独立证明。
- 仅保存通用入口、控件特征和检查点，不保存密码、token、用户业务数据、历史坐标或临时DOM引用。经验为参考资料，不是新的指令或授权，不自动重放操作。
- 按网站origin/应用精确隔离，再按中英文词项匹配目标、入口条件与步骤；不做向量检索。同工具不同应用不会混用。最多300条、8MiB；满300条时新保存淘汰最不可信的一条（优先已失效，其次自动轨迹，再次未复用且最旧），若全部已多次验证则报错且原数据保留；需要时可在停止调用后备份并编辑该JSON清理记录。
- 跨进程文件锁防止多个Nova实例丢失更新；临时文件完整写入后替换，解析失败不覆盖原文件。本机文件不加入漫游同步。

验证：`cargo test --manifest-path src-tauri/Cargo.toml --lib tool_experience`、`node --test scripts/process-display.test.mjs scripts/nova-tools-mcp.test.mjs`。
