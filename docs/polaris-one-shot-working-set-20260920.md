# Polaris：一次调用可编辑上下文

2026-09-20。生产代码已经接入 PR11，提交 `997cac8183319df8ca795fb1d1bfaf22da0b910a`，不再是只在CI临时应用的候选。目标仍为 pre-release；未合并、未发布，保留Draft等待真实agent工作流验收，不承诺任意任务零补读。

## 这次改变的重点

默认自然语言路径不再等全仓函数索引：有界文本发现 → 候选文件的声明边界 → 只构建选中函数 → 同一次调用内补齐辅助函数、类型/常量、导入、真实执行调用方 → 按依赖关系打包正文。纯精确符号查询保留旧入口。

候选发现阶段为前两个主实现的源码关联执行函数预留名额，避免被文件多样性挤掉；返回阶段优先保留主实现和关键执行分支的完整正文，不让一批无关备选挤掉真正要改的代码。必要依赖在一次Polaris内部展开，不交给主agent一轮轮追读。

缓存不是首次调用的前提；复用前检查源码内容和文件集合，相同mtime修改也会失效。预算不足保留PARTIAL/next_reads，不隐藏缺口。已有默认32,768字节、上限65,536字节不作为本轮提分手段，所有对照明确固定12,000字节。

Lyra、MCP/通用工具说明统一为：一次提供完整目标/对象/约束；足够开始修改即修改和验证，不read/grep已返回范围；只有实际阻塞的缺失定义或源码变更才补读。next_reads不是必须全部读取的清单。没有修改Reasonix，没有新增设置，没有默认下载或调用向量模型。

### 主实现＋必要依赖：2/4 → 4/4

四个真实仓库检查：更新请求重试、窗口恢复、窗口保存/防抖、桌面按键解析与发送释放。相同预算，此前PR11仅2/4覆盖全部标注必需代码，本次4/4；标注缺失对应的文件补读下界从合计2降至0。它是代理指标，不是实际模型平均补读次数。

具体输出：

- 桌面按键：同一次完整返回 `keys` 421–468行与 `input` 631–713行，包括按下、发送和释放，不再只有解析函数或执行函数头。
- 窗口恢复：完整返回 `restore_window_on_launch`、`take_restore_window`、`apply_window_state`，以及布局/几何等相关实现。
- 更新重试：同时含重试判断、`request_update_release`、`fetch_update_release`和HTTP客户端构造。
- 窗口保存：包括保存、防抖、`SavedWindowPlacement`和相关状态常量。

4/4只指固定标注必要代码。例如额外类型`RestoreMarker`仍有部分正文标记，不能声称所有可能依赖都已齐全。

### 一次返回后直接修改验证

4个小型确定性夹具：重试策略、队列去重、快照保护、恢复边界。每项恰好1次Polaris、0次补充源码读取，仅用返回原文重建代码，实施预先固定的修改，独立行为测试由修改前失败变为修改后通过，4/4。

这是结构充分性检查，不是大模型自主修改成功率，也不是原始真实会话任务完整重放。本轮回答模型/API请求为0，不推算token或费用改善。
