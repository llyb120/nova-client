# 剑来（jianlai）

支持按任务检索、成功后提炼和复用反馈的本机[操作经验](tool-experiences.md)：`experience_search` / `experience_save` / `experience_feedback`。

系统级桌面工具，和 `chrome` 并存；浏览器网页操作仅用 `chrome`。通过 Enigo 注入原生鼠标键盘事件，通过 XCap 获取程序窗口和显示器截图；不使用 Playwright、DOM 或辅助模型。

- `windows`：列出程序名称、窗口标题、PID、windowId、尺寸及monitorId；1x1等辅助窗口不适合交互。
- `screenshot`：优先传 windowId 截目标窗口；省略则返回全部显示器独立图片（最多16屏）；已知monitorId时可只截一屏，不能同时传windowId。默认长边最多1600像素；`maxEdge: 0` 使用原分辨率，否则允许640–3840。
- `act`：传 snapshotId、imageId 和 actions（1–16项），默认返回实际前台应用窗口的新截图，自动跟随新窗口/弹窗；任务视图等不可独立捕获的系统界面回退桌面。feedback=desktop可保留操作屏幕以观察窗口外菜单。返回imageId/坐标范围可能变化，下一步必须使用新图坐标。`feedback: "none"` 可省略截图，但下次操作前必须重新截图。
- 点击、双击、移动、拖拽、Unicode文本输入、组合键、双轴滚动和有界等待均为真实系统输入。坐标以**实际返回的图片像素**为准，服务端同步映射缩放、负坐标屏幕和Retina坐标；act继承快照的maxEdge。
- `wait.ms` 仅允许0–2000，默认250。整批预校验：`actions[1].ms=8000，允许范围为 0–2000；本批次尚未执行` 意味着前面的点击也没执行。
- `recall(imagePath)` 回看本会话历史结果的图片，不创建可操作快照，也不改变当前快照。旧图仅用于阅读，操作必须绑定当前观察。
- `notes` 用于滚动前记录已读条目、覆盖范围和未确认项（最多12000字符），原样作为文字保留，不代表工具已核实。请求“可用/测速”应定位后先单独触发测试，再观察和必要的短等待，不能把数节点当成验证。

示例：

```json
{"operation":"windows"}
{"operation":"screenshot","windowId":123}
{"operation":"act","snapshotId":"上次返回值","imageId":"window-123","actions":[{"action":"click","x":180,"y":90},{"action":"type","text":"你好"}]}
```

窗口输入要求目标在前台；后台窗口可以截图，但不能盲目操作。窗口截图不会激活窗口。Windows上用activate(windowId)切到前台并直接返回新图；系统拒绝激活时才截桌面，用Win+Tab加wait 250ms显示任务视图或点击可见任务栏图标。不要盲目循环切窗或猜应用热键，同一路径连续失败两次应报告阻碍。用户指定剑来时，整个桌面任务只用剑来鼠标键盘与截图，禁止shell、COM、PowerShell、P/Invoke、UIAutomation及终端脚本操控应用。窗口位置/尺寸、焦点、显示器布局发生变化会拒绝旧坐标。快照180秒过期、仅消费一次，并绑定当前Nova会话。全局锁防止剑来并行操作同一桌面。批量动作只用于已确定的连续步骤；需要根据画面判断时拆分调用。批次内焦点改变且仍有后续输入时停止并返回新图，不把剩余键盘输入送进未知窗口。用户同时移动窗口/输入仍可能产生竞态，请操作时避免争用桌面。

`not_executed` 表示尚未发送输入。焦点、窗口几何或快照过期等目标校验失败会直接附带当前截图、新snapshotId、foreground与desktopBounds（即使feedback=none），不自动重放；窗口失焦、关闭或最小化时跟随实际前台窗口，无法捕获时改为桌面观察，原因保留在windowObservationError。不能根据焦点变化猜测是哪一个程序抢焦点。

`executed` 表示输入已发送，不表示应用任务成功；`needs_review` 表示可能部分执行，检查completedActions/error和随附新图，禁止重放整个批次。观察失败会单独返回observationError，不掩盖执行状态。

## 后台操作（macOS / Linux）

`windows`、`screenshot`、`act` 带 `background: true` 时，不动用户的真实光标、键盘焦点和前台窗口，用户可以同时使用电脑。后台不占输入闸门（不挡 Chrome 工具），也不计入「刚注入过输入」，因此不会掩盖用户自己的操作。

| 平台 | 机制 | 范围 |
|---|---|---|
| macOS | 事件用 `CGEventPostToPid` 直接投递给窗口所属进程，截图取窗口自身像素（被遮挡也行） | 必须传 `windowId` |
| Linux | 在 Nova 私有的 Xvfb「座席」里操作（首次后台调用时自动拉起，Nova 退出即被带走），用户的 X 会话完全不受影响 | 只有桌面视图，不传 `windowId`/`monitorId` |
| Windows | 只有一个输入队列，不支持 | 返回错误，不会改用真实输入 |

- **模式一致**：后台快照只能用 `background: true` 的 `act`，前台快照反之；不一致直接 `not_executed`。后台请求绝不回退到真实输入。
- **Linux 座席**：`windows(background:true)` 返回 `background.display`（如 `:200`）。先在 shell 里用 `DISPLAY=:200 firefox &` 启动要操作的应用，再截图和 `act`。座席没有窗口管理器，所以没有窗口列表；整个进程共用一个座席（`ponytail`：按会话隔离时改为 owner → 座席的表）。座席重启后旧快照因屏幕标识变化而失效。
- **macOS 前提**：授予 Nova「辅助功能」（缺失时系统会静默丢弃事件，工具会提前报错）和「屏幕录制」。键盘最稳；点击、滚动个别应用可能不响应。点击若让应用自行把窗口提到前台，结果带 `foregroundChanged`，此时停止并改用键盘。
- **macOS 键位**：组合键按 ANSI/US 物理键位解析，非 US 布局下 `Cmd+字母` 可能对应到别的字符。
- 后台下 `activate` 不可用；`glide` 在 macOS 后台被忽略（没有可见光标）。

## 观察与结果验证

纯 move 定位反馈直接返回单帧（not_checked），不增加稳定等待；需等待悬停菜单/提示时使用 move + wait。包含其他动作或执行状态为 needs_review 的反馈仍做稳定取样。稳定取样在编码前每隔约150ms取样，至少观察600ms，并要求连续450ms画面近似稳定；2秒取样预算耗尽返回最后一帧及 images[].stability.status=timeout。单次系统抓屏耗时无法中断，失败后的桌面回退另有一次预算。中间帧不落盘、不发送；主动 screenshot 和未执行输入的恢复截图保持单帧，标记 not_checked。feedback=none 仍不取图。

比较使用原始像素、忽略透明度，允许0.05%的像素发生明显颜色变化，以容忍光标闪烁和微小噪声。此启发式可能漏掉很小的更新，也可能被持续动画拖到超时；stable 不代表网络请求结束。必须继续核对目标、选中项/筛选条件与正文一致，无法确认时只重新观察，不重放操作。

新图通过 snapshotId 标识一次观察，observationSequence 是进程内递增序号（重启重置）；每张图附 snapshotId、capturedAt（UTC）和稳定取样统计，窗口/屏幕范围沿用 windowId、imageId 与 desktopBounds。operation 标明来源，操作结果的 basedOnSnapshotId 指向输入依据。historical=false 仅表示本次新采集，并非永远有效；recall 仍标记 historical=true，不伪造原图采集时间或新快照。

所有操作结果均为 verification=unverified：工具能确认输入执行状态，业务目标需模型依据最新图判断，但该字段不要求额外检查。速度优先：最新动作反馈已满足目标就立即汇报并结束，禁止再截图、查状态、等待或二次确认；仅有明确未完成证据时才做一次针对性复查，没有新信息就报告未确认项，不循环截图。结论须绑定已有截图及可见证据；未检查完整范围不能声称“全部”或“不存在”。notes 仍原样返回，须记录来源snapshotId和页面范围，不能跨页面混用；工具不验证笔记内容。本改动不删除、裁剪或压缩任何宿主的历史上下文。

## 上下文机制与适用范围

缩放、坐标映射、校验与恢复、回看、notes以及截图耗时均在共享jianlai服务层实现，Lyra原生工具和MCP调用使用同一套契约与策略说明。

**本次不实施历史图片裁剪，也不要求宿主淘汰旧图。** 各后端仍按各自原有机制管理历史、请求组装、缓存策略、容量统计及上下文压缩。优化仅从新截图的尺寸、目标范围、调用策略和失败恢复入手，因此历史截图累计问题并未由本次改动解决。

滚动阅读先写notes，未记录信息可recall回看。一批act里连放多个scroll时，每个非末尾scroll后自动附一张只读中间帧（`images[].frame`为该scroll的序号，附`framesNotice`），一次调用读完多屏；中间帧只供阅读，后续act仍只用顶层snapshotId与最后一张图的坐标。不会删除本地旧图或重开会话来伪装上下文优化。

## 耗时诊断

NovaDev对xcap、image、png及压缩依赖启用优化编译；稳定取样先做整帧字节相等比较，静止画面无需逐像素扫描；缩放通过DynamicImage进入依赖内的优化实现，保留Triangle算法和相同像素尺寸。目标校验复用同一次窗口枚举完成几何与遮挡检查，不缓存到下一动作。纯图像基准可运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib jianlai::tests::screenshot_pipeline_benchmark -- --ignored --nocapture`，输出缩放/编码耗时，并验证与原缩放实现及PNG解码结果逐像素一致；此测试不操作桌面。

截图返回timingsMs：capture（系统捕获）、resize、encodeAndSave（PNG编码及落盘）、other（窗口枚举、焦点校验等）和total。MCP传输适配另返回deliveryTimingsMs（read/base64/total）及deliveredImageBytes；不包含网络及模型耗时。Windows前台身份检查直接读取窗口句柄与PID，避免每个动作多次枚举所有窗口及其元数据；这是只读状态检查，不负责激活。先比较这些分段数据，再决定是否换捕获后端/编码器，不据单次总耗时猜测瓶颈。

## 平台与构建

- Windows：普通桌面；系统安全桌面/UAC及高权限程序可能阻止输入或截图，不自动提权。
- Windows可见提示：剑来**任意一次调用（含第一次观察）**即在屏幕边缘点亮天蓝呼吸光效，并把系统指针换成剑尖带天蓝墨点光晕的剑，用户在模型还在看图时就知道剑来接手了；之后只要有Nova会话回合仍在运行就保持（两次调用之间不断开），回合结束即收起，回合仍在跑但3分钟未碰桌面也收起；外部MCP调用方看不到回合状态，保持20秒。`background:true` 不碰用户的指针与前台，因此不点亮。光效层设为WDA_EXCLUDEFROMCAPTURE、鼠标穿透、不可激活，并以无标题工具窗口避开窗口枚举，不进入截图、前台与遮挡校验；系统不支持排除截图（早于Windows 10 2004）时只报一次并永久不显示。截图本身不含系统指针，换指针样式不改变任何截图像素。指针在光效隐藏、Nova退出及下次启动时按用户指针方案恢复。
- macOS：需授予 Nova 屏幕录制与辅助功能权限。
- Linux：输入仅支持 X11，需支持 EWMH 的窗口管理器；Wayland 输入明确拒绝，不回退到只能控制部分窗口的 XWayland。
- Linux 官方构建基线为 Ubuntu 24.04（glibc 2.39）；产物不保证兼容 Ubuntu 22.04。XCap 使用的 libspa 0.10 与 Ubuntu 22.04 自带的 PipeWire 0.3.48 头文件不兼容，不能只安装同名开发包解决。
- Linux 新增原生构建依赖（Debian/Ubuntu）：`libpipewire-0.3-dev libspa-0.2-dev libgbm-dev libclang-dev`，以及原有 Tauri GTK/WebKit 构建依赖。

截图保存到 Nova 配置目录的 `desktop-shots` 下的会话隔离目录，可能含敏感屏幕内容；旧图仍保留供按需回看，按需手动清理。升级前平铺保存的图片不支持新的recall入口，但原文件不删除。模型必须支持图像输入才能闭环操作。

## 验证

`cargo test --manifest-path src-tauri/Cargo.toml --lib jianlai` 验证坐标、按键与参数边界。

`cargo test --manifest-path src-tauri/Cargo.toml --lib jianlai::tests::desktop_smoke -- --ignored` 在真实桌面验证截图→鼠标移动→截图及拒绝重放（只移动指针，不点击或输入）。将测试名换成 `jianlai::tests::pointer_reaches_each_monitor` 可在Windows以Per-Monitor V2 DPI感知验证所有显示器的边缘、中心及负坐标落点（瞬移与真实输入路径点两种方式），结束时恢复指针，不产生截图。两项都只在空闲的测试桌面手动执行。

## 操作调度与定位

批次内点击/双击和输入文字之后保留300ms，让应用弹出搜索框、下拉或刷新搜索结果后再接收下一个输入；按键、滚动等之后保留80ms基础处理时间；显式wait前后、move之后不叠加80ms，最后一项动作之后直接进入原有反馈取样，不再多等80ms。无需每个动作都追加400–900ms等待；只有已观察到加载或动画时再加短等待。scroll必须直接提供x/y/delta，自带鼠标定位，无需先move。click/double_click/move/drag 默认走拟人轨迹（`glide:false` 瞬移，scroll 始终瞬移定位）：时长随距离按 Fitts 定律在80–400ms内增长，最小加加速度缓动，随机±10%弧度，按实际耗时取样以免粗粒度 sleep 拉长；终点精确落在目标后仍做落点读回校验。默认开启以便用户看清指针去向；途中经过的元素会收到悬停，途经区域的悬停会弹出干扰浮层时改用 `glide:false`。drag 的按下段仍只在显式 `glide:true` 时走轨迹，否则沿用12步直线。相同已确认输入区的点击与输入可合批，跨页面、弹窗、对象确认仍拆分观察。输入框点击编辑区内部，避开工具栏；不清楚时先用窗口图定位，不盲点。窗口切换后的windowId仅选择反馈范围，不会通过系统API激活窗口。

## 应用规则的渐进式披露

每个应用的操作方式不同，但核心提示词必须保持泛用：各应用的规则单独写在 `scripts/jianlai-apps.json`（`match` 按应用名与窗口标题小写子串匹配，`rules` 为该应用的短规则），只有 `windows`/`screenshot`/`activate` 真的观察到该应用时，才把这一份规则作为结果里的 `appRules` 追加，每轮对话每个应用仅一次（与 `experienceHint` 共用 `once_per_turn` 去重，随 finish_turn 重置）。没写规则的应用不追加任何额外提示词。规则是操作参考，不扩大用户授权；新增应用只改这个 JSON，不动核心提示词。

## 局部定位与失效快照恢复

Windows截图会在系统读取的实际鼠标位置绘制与系统指针同款的剑形标记（系统截图本身不含指针），剑尖即落点，`images[].cursor`给出剑尖在当前图片内的坐标。标记只绘制在反馈图中，剑身会遮住剑尖右下方约20像素；剑尖光晕在反馈图里刻意比真实指针淡得多（`MARKER_GLOW` 对 `CURSOR_GLOW`），压住的内容仍可读，不干扰模型判断；点击前的像素守卫仍比较未绘制标记的原图。截取前后鼠标位置不同、鼠标在图外或截图为后台窗口时不标记。小目标或定位不确定时先单独move，看新图确认落点后再click；不要把待确认的move与click合批，也无需给每次点击增加往返。标记只证明鼠标落点，不证明识别的目标正确。

Windows前台窗口从所在显示器的实际画面裁剪，保留窗口范围内独立弹出的候选框，避免PrintWindow截图遗漏浮层。窗口外菜单仍用feedback=desktop；跨屏、部分离屏或像素比例不一致时窗口裁剪拒绝执行，自动反馈回退桌面，显式screenshot可改用monitorId。后台窗口仍可独立截图，不能据此操作被遮挡内容。

Windows的press字母/数字按虚拟键发送，Ctrl+A与Ctrl+a等价；大小写文本使用type，组合键的大写由显式Shift控制，避免Enigo将大写字符的修饰位误当成键码。

`screenshot`指定windowId时可加`region:{x,y,width,height}`，区域以原始窗口图片originalWidth/originalHeight像素为准，先裁剪再按maxEdge缩放。返回图可直接用局部图片坐标act，工具负责偏移、缩放与负屏幕坐标映射；窗口几何校验仍检查完整窗口。act后的反馈恢复完整前台窗口，必须按新图重新定位。局部截图不读取DOM、UIAutomation或其它语义控件接口。

缺少或误用旧snapshotId时，若本会话、同模式的最新快照未过期且未作废，act返回not_executed、snapshotPreserved和nextArguments，不重新截图、不延长快照寿命。使用已有最新图重新决策剩余动作，不重放已执行动作；下一次输入仍检查前台、几何和落点。没有可用快照或确实失效时才获取新观察。另一会话持有的快照仍拒绝访问，不覆盖它。只允许最新截图操作，查看其它窗口会替换当前快照；旧图回看使用recall。

窄输入栏或地址看不清时先局部截图；一次误点后不要继续猜坐标。联系人以完整地址和已提交标签核实，红色错误标签不算成功；下拉列表变化后重新定位。正文在确认焦点后整段输入，误输入先确定内容和选区，不靠盲目Backspace试错。用户要求只准备草稿时，禁止发送和发送快捷键。

## 精准定位增强

`regionSpace=image` 可按最新返回图片的像素给出局部裁剪区域，必须同时提供该图的 `snapshotId/imageId`；工具反算裁剪和缩放，重新采集细节图。默认 `regionSpace=source` 兼容原始图片坐标，需要 `windowId` 或 `monitorId`。局部图生成后旧快照失效。

点击/双击/拖动前检查未绘制鼠标标记的原始落点邻域（滚动不检查：同一点连续滚动必然改变画面，且滚动可逆）。Windows瞬移用SetCursorPos直接接受桌面坐标；拟人轨迹及拖动的路径点先发送按虚拟桌面归一化的SendInput真实输入，再用SetCursorPos校正，避免Enigo按主屏归一化造成多屏偏移；移动后读取系统实际位置，各轴允许最多2个原生像素的舍入误差，超过仍停止按钮输入，不做猜测补偿。轨迹移动、落点后、拖动、滚动和输入文字期间前台被其他窗口（通知、弹窗）抢走时切回原前台继续，切不回才停止，不当作用户中断（只有用户按 Esc 才中断）；动作开始前前台已与截图不一致时，窗口快照的报错直接提示 activate(windowId)，无需先重新截图；第一次点击后前台变化也不继续双击第二次。保留原有反馈稳定检查。像素守卫是启发式，不是控件识别，不承诺捕获所有视觉变化或竞态。

本轮未在 Windows 编译和执行原生输入链；新原生单元测试和验收入口见 [精准交互说明](automation-precision.md)。

### 切窗和裁剪恢复

Windows 用 activate(windowId) 激活 windows 返回的窗口并取得新截图；windowId 不是 pid。系统拒绝激活时不会发送后续按键。单图快照的纯 press/type/wait 批次可以省略 imageId；坐标动作、多图和显式错误 ID 不做猜测。ID 错误返回当前可用 ID，无需额外截图。裁剪图坐标从左上角 (0,0) 开始，不加 region 偏移；以返回的 width/height 为准，操作后反馈恢复完整窗口。

### 局部放大与失败反馈

裁剪截图设置 maxEdge:1200 会等比放大到长边1200，maxEdge:0保留原像素；完整截图仍只缩小。工具自动映射放大图坐标。坐标校验或鼠标输入失败只返回正常的新反馈，不再自动附加同一画面的3倍放大图；确实看不清时再用regionSpace=image获取原生局部细节。不会自动判断业务目标是否点错或重放动作。

批量滚动只在后面还有非wait动作时保留只读中间帧；末尾scroll+wait直接使用最终反馈，避免重复。feedback=none同时关闭滚动中间帧；实际失败仍附恢复所需的新反馈。

## 剑谱（用户演示录制，Windows）

用户亲手演示一遍桌面操作，录成「剑谱」，再交给 AI 整理成剑来知识图谱路径。

- **开始/停止**：全局快捷键（默认 `Alt+R`，设置 → Meteor 页可改或关闭），或 Butterfly 面板 →「星海」→「剑谱录制」（面板左侧分「会话 / 星海」两个标签：鼠标停留弹出时默认「星海」，单击 Butterfly 默认「会话」摘要）。停止时只收起光效并静默保存，不打开剑谱页（失败才弹系统通知）。单段最多 10 分钟 / 200 次点击，到上限自动停止。
- **提示**：录制中屏幕边缘是暖金色慢呼吸光效 + 左上角「剑谱录制中」，开始时从触发处荡开一圈水波，指针换成琥珀描边的奶油色箭头 + 右下录制圆点；剑来是天蓝光效 + 剑形指针。两者互斥：录制中剑来拿输入闸门直接失败（`not_executed`），剑来正在操作时不能开始录制。光效窗口排除在截图外。
- **录什么**：低级键盘/鼠标钩子只监听不拦截。鼠标按下时截所在窗口（找不到窗口截所在显示器），红圈标出落点，长边 1280 存 JPEG；按下/抬起配成点击、双击、右键、拖拽；连续同向滚动合并；打字按原文合并（退格删字），输入停顿 400ms 或一段输入结束时用 UI Automation 读焦点输入框内容记为 `value`（输入法输入只能靠它拿到中文原文）；修饰键组合记为按键。在 Chrome 窗口里点击时，用 UI Automation 读地址栏，把页面地址记到该步 `url`。带 INJECTED 标记的输入（剑来注入）和落在 Nova 自己窗口上的操作不录，停止录制的那一下快捷键也去掉。
- **存哪里**：Nova 配置目录 `jianpu/<id>/`（`recording.json` + 截图）。打字内容（包括密码）按原文明文保存，不自动清理、不漫游；删除剑谱不影响已存进图谱的路径。
- **学习**：剑谱页点「交给 AI 学习」，用 Meteor 的执行后端/模型在临时目录开新会话，提示词只含步骤 JSON 和截图目录，模型按需 read 截图（不把图片塞进提示词）。模型按应用拆分、去掉试错，必须输入指定内容的原文写进步骤，会变的内容只写方法，然后 `experience_save` 带 `experience.recordingId` 直接存图谱：桌面应用用 jianlai（scope 须是剑谱里出现过的 app），带 `url` 的 Chrome 网页步骤用 chrome（scope 须是剑谱里出现过的网站 origin，步骤按网页控件写），recordingId 代替 180 秒内观察的来源校验，标记 `source=demo` / `verification=user_demonstrated`。
- **查看**：知识图谱页右上角「剑谱」按钮进入剑谱页，按时间线查看每一步的截图、应用、原文输入，以及生成的图谱路径；知识图谱的路径详情有「查看剑谱」回链。

已知上限：截图在按下后由后台线程截取，菜单在按下时就弹出的应用会拍到已变化的画面；UIA 读值是异步的，回车即发送并清空的输入框可能读不到 `value`（仍保留按键文字）；ToUnicodeEx 用不改内核键盘状态的标志（Win10 1607+），更早系统上死键组合可能被打断。
