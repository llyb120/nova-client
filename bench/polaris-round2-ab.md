# Polaris 第二轮：慢路径治理、索引更新与 Command Code GLM A/B

## 基线与结论

上一批已提交为 `96c93c5`（无变更符号快照复用、请求内正文共享）。本轮 A 为该提交的原生模块，B 为本轮最终模块；不是与最初 `30126f7` 实现比较，不能再次计入上一批的收益。

结论：采用慢路径约束、后台索引更新和召回缓存正确性改动。**热检索基本持平，未证明完整对话提速**；受控增量更新明显减少复制。普通查询的证据内容未在这批样本中发生变化。

## 本轮落地

1. **请求内固定检索快照与搜索预算**：入口只选择一次全文快照；没有快照的请求保持实时 rg 路径，不因后台索引发布在中途改用另一份索引。初搜、计划补搜、动态调用方补搜、拼写建议与自动纠错重试共用 3 秒搜索截止时间。截止后不继续补搜，并明确输出 `CTX PARTIAL` 或覆盖不足提示，不把超时说成符号不存在。该预算不是整个工具的硬超时：索引构建、CPU 打包、锁等待、历史查询仍有独立成本。
2. **失败不再重复工作或冒充成功**：rg 搜索失败不再重复回退扫描相同范围；git grep 后备路径也受预算和输出上限约束。Git/rg 子进程检查退出码（rg 的 1 为正常零命中），超时/失败的共改结果不缓存为“无共改”。Git 小命令和文件列表命令增加时限。达到搜索输出字节上限时提示不完整。
3. **历史查询重叠与合并**：伴生测试的 Git 共改查询在种子确定后提前启动，与正文/图分析重叠；同 HEAD+种子的并发查询使用同一计算结果，不持全局锁等待。复用当前请求的 revision，减少重复 Git 子进程。仍等待并使用历史结果，未为了速度删除首次测试召回。历史失败会提示伴生测试/耦合覆盖可能不足。
4. **全文增量索引减少全量复制**：内容、词表、倒排列表使用 `Arc`，只复制变动列表；累计 delta 中正文未变的条目不再重复分词或改写倒排表。构建发布不再深复制整个快照；落盘格式未变。
5. **连续编辑刷新修复**：Git porcelain 的 `M` 不变时也检查脏文件 size+mtime，避免连续编辑漏刷新；覆盖删除、载入旧脏快照等边界。尚未复核的磁盘快照及长时间未更新的内存快照不直接用于查询，先走实时 rg。
6. **闲置项目停止磁盘轮询**：一分钟无请求后跳过 Git/文件扫描；下一次查询恢复。保留轻量线程等待，不销毁重建。活跃项目仍按原来的约 2 秒周期更新，并非文件系统事件级即时一致。
7. **反向图批量更新**：删除旧引用边时一次遍历图，用变更 importer 集合过滤，不再每个变更文件重复遍历全图。
8. **知识召回按项目缓存**：首次只构建目标项目+泛用知识的召回快照；保存训练日志/计时器等无关状态不失效，实际知识/激活权重变化才失效。修复“构建旧快照期间保存使缓存失效，随后旧快照又被发布”的竞争窗口。构建时不持召回缓存锁，其他项目热召回不必等。
9. **分段诊断**：增加检索后端、Git 历史计算/剩余等待、Lyra 代码和知识分支（含线程排队）计时。知识仍与代码并行且等待完成，不静默丢弃规则召回。

## 正式 A/B

复用上一轮驱动与三项任务，`--baseline 96c93c5 --corpus-ref 30126f7`。语料固定为原提交的 `src-tauri/src`、`src`、`scripts`，不含新评测脚本或新答案。导出语料仅有一个合成 Git 提交，**不反映真实长历史仓库的 git log 收益**。

两侧同一 Rust release 二进制、生产搜索配置、独立缓存、交错调用。每任务 6 对，排除第 0 轮，剩余 5 次取中位数：

| 查询 | A / ms | B / ms | B 相对变化 |
|---|---:|---:|---:|
| 索引读取与发布 | 77.84 | 76.94 | 快 1.2% |
| 工具执行与预算治理 | 50.57 | 51.22 | 慢 1.3% |
| 系统提示词与只读模式 | 33.91 | 33.09 | 快 2.4% |

15 对热查询逐字一致。多次开发期复测有正负波动，因此不将以上小幅差异解释为稳定提速。

额外 3 对独立空缓存进程冷查询：A 为 271.03/215.58/148.11ms，B 为 196.90/172.01/155.17ms，3 对输出均一致；B 的三个请求均记录 `rg/fallback`。不是冷 OS 缓存，不是大样本 P95 测试，不能据此承诺所有冷启动等价或固定提速比例。回归测试另断言请求不会采用中途发布的索引。

## 增量更新受控检查

同一优化构建内，1500 个合成源码文件，固定持有旧快照，连续 8 次更新同一文件并重放累计 delta；排除第 0 次后取中位数。直接调用两侧原有 `apply_search_delta`，不计语料构建、Git 扫描或写盘：

| 操作 | A / ms | B / ms |
|---|---:|---:|
| 单文件更新 | 1.9139 | 0.2956 |
| 相同 delta 重放 | 1.9406 | 0.000652 |

更新计算减少约 84.6%；重放几乎只做相等检查。仅代表该合成内存更新路径，不能外推为完整后台更新提速。回归测试同时检查旧快照不变、未改正文/倒排共享、delta 幂等和删除处理。

## Command Code GLM-5.3-Flash

实际请求及响应均为 `z-ai/glm-5.3-flash`。3 任务 × 2 次交叉顺序 × A/B，共 12 次正式调用；每次新会话，注入该侧最后一轮 Polaris 证据，模型不能再调工具。温度 1、top_p 0.95、输出上限 3000 token，无自动重试。凭据只从本机既有配置读取。

| 指标 | A | B |
|---|---:|---:|
| 正常完整返回 | 6/6 | 6/6 |
| 关键符号字面命中 | 10/10 | 10/10 |
| 辅助事实词命中 | 13/18 | 15/18 |
| 输入 token 总计 | 41,216 | 41,216 |
| 输出 token 总计 | 4,895 | 5,089 |
| 模型请求平均耗时 | 23.86s | 26.65s |

**没有模型侧提速或输入 token 节省**。两侧证据逐字一致，字面命中差异只能视为回答随机性，不能宣称召回质量提升。词命中不是语义正确率，模型仍可能对签名/实现活跃路径作不严谨推断。

该测试不是完整 Agent 多轮任务，也不覆盖 Lyra 知识召回的实际线上耗时。知识侧变化由针对性原生测试验证，未测出全库规模下的延迟收益。

## 验证、剩余边界

- 48 项上下文测试、4 项经验库测试、2 项常驻服务测试、8 项 Lyra 工具测试通过；2 项既有排序实验保持 ignored。
- 同仓库符号索引冷扫描仍持更新锁，变动时仍可能复制符号缓存；未为此做高风险并发发布重构。
- 全文外层 HashMap 仍有 O(键数) 浅复制，累计 delta 落盘仍有复制/序列化成本。请求固定索引不会消除既有轮询新鲜度窗口。
- 确认“空补搜结果”的缓存仍未采用：必须先能区分真零命中、候选裁剪、行数上限和不完整扫描，避免错误省掉补搜。
- Git 共改仍有最多约 750ms 的计算上限，重叠计算并不保证完全隐藏等待；并发锁等待和极端磁盘卡顿不构成整工具严格硬上限。
- 项目召回缓存最多64项，写路径需比较缓存知识内容；尚未改为分区版本号，也未重构经验库整文件持久化。
- 当前 `/opt/nova/nova` 进程未部署更新，正常构建并重启后才会生效。
